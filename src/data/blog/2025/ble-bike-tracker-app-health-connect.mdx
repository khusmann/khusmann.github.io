## Building The Firmware + App

When I started this project, my original plan was to run an http server on a Raspberry Pi that the ESP32 would connect to via WiFi. I figured I could have the firmware push my activity to the Pi via a simple REST API, then the Pi push my activity sessions to Google Fit via the [Python API](https://developers.google.com/fit).

Unfortunately, as I quickly found out, the Google Fit API will be deprecated in 2026. In fact as of 2024, new developers can't sign up to use these APIs. Instead, developers are being encouraged to migrate to [Health Connect](https://developer.android.com/health-and-fitness/health-connect/comparison-guide) instead. (I could have also used the Fitbit Web API, but I was leery about this given Google's [slow killing of Fitbit](https://www.tomsguide.com/wellness/smartwatches/google-is-slowly-shuttering-fitbit-should-you-still-buy-one))

The downside to using Health Connect is that it's an Android API, not a REST API. So if I wanted to sync my data with Google Fit, I'd need to build a mobile app.

I've done quite a bit of mobile app development, but it's all been in [React Native](https://reactnative.dev/) with [Expo](https://expo.dev/). Although libraries exist to wrap Health Connect and BLE in React Native, they would have required custom managed builds in Expo (see [this](https://github.com/matinzd/react-native-health-connect?tab=readme-ov-file#expo-installation) and [this](https://github.com/dotintent/react-native-ble-plx)). For me, the whole fun of React Native is the ability to preview in Expo Go without building... so I resigned myself to build an actual native Android app.
